# 生成失败恢复

每个失败任务**只做一个决策**，且必须四选一：**调整后重试 / 原样重试 / 问用户 / 停止**。
按错误类型判定，不猜：

1. **内容策略/提示词错误**（报错含内容拦截、违规词、provider 拒绝）→
   **调整后重试**：删除或安全替换违规表达，保留用户创作意图。
   禁止编码、混淆或以任何方式规避供应商安全策略。
2. **参数错误**（报错点名了具体参数——分辨率/画幅/模型不支持、非法组合 400 点名镜头）→
   只有确认该参数确实有问题才**调整后重试**，只改出问题的字段，其余字段原样保留，不重发全量。
3. **限流/服务端异常**（HTTP 429、5xx、网关超时、Broken pipe）→
   **原样重试一次**（提示词与参数一个字不改）；再失败就停止并如实报告。
4. **用户硬约束导致**（点名的模型/画幅/参考图不被支持、画风闸拦截、余额不足、
   附件/参考媒体有问题）→ **问用户**：把问题写成用户可以直接回答的一句话
   （画风闸则引导去底部坞「画风」选择），不要替用户改选。
5. **鉴权、权限、取消、超时、网络、轮询、下载、工具参数被截断和未知错误** →
   **停止**并报告，不得猜测性调整。

通用纪律：

- 一次失败只给一个决策；不新增任务、不换工具、不扩大操作范围、不动用户没提的卡片。
- 同一任务调整重试**连续两次**仍失败 → 升级为问用户，不要第三次盲试。
- 卡片状态如实：重试前置回 loading；放弃则置 `{status:"error", errorMessage:原因}`，
  绝不让卡片停在 loading。
- 向用户报告时用简洁中文说明依据（哪个错误 → 哪个决策）；问用户时只问一句能直接回答的话。
