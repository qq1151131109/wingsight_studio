# 资产感知生成

出图前先对齐画布现状，不要凭空画：

1. 先查画布已有资产：`canvas_query({types:["character","scene","prop","costume"], query:名称})`。
   同名/同题材资产卡已存在时不要重建——引用它的设定图保持一致。
2. 一致性参考：generate_asset_images 的 assets_json 每项可带
   `reference_images`（画布摘要或 `canvas_query({resourceOnly:true})` 里的
   /agent-service/assets/ URL）与 `reference_labels`（如
   `[{"type":"character","name":"郑成功"}]`，type=character 时锁身份、不继承
   参考图的白底排版）。用户说「按某角色的设定图出」「保持形象一致」时必须带上。
3. 考据按**资产本尊**判定（题材只由用户声明决定，不凭历史题材自行推断）：
   资产本身涉及真实朝代人物/地点/制度/宗教服饰/官服/器物——哪怕整片是虚构
   故事——就按考据方向准备参考；纯虚构资产不必。
   **题材口径**：项目分「真实题材」（历史/罪案纪实等，缺省）与「虚构」
   （动画/架空/穿越）。真实题材出图时服务端会为**没有考据简报**的资产自动
   补一次文字考据（年代/形制/常见误用）并注入提示词，同一资产不重复搜、
   同题材主体可跨项目复用——你不用手搬，也不必在 visual_notes 里手写考据；
   用户说做动画片/虚构片时调 set_project_factuality("fiction") 声明，之后
   不做史实考据。（摘要「题材：」行就是当前口径，据此判断。）
   **复用有读面了，发起之前先看一眼**：调 `list_research_library` 列同题材
   项目已考据过的主体（事实 + 参考图张数 + 来自哪个项目 + 本项目是否已引用），
   命中就用 `import_research` 引用（活引用：不拷正文，源更新跟着变），不必重搜。
   画布上的入口是考证报告卡工具条「同题材库」。
   **库按时代分域**：作用域键是项目 meta 的 `era`；**没设 era 的项目库是空的**
   （主体只在项目内成立），所以真实题材调研前先确认年代已记下——agent 用
   `set_project_era`，用户可在报告卡工具条「年代」上填。架空/穿越不设。
   **参考图也随主体跨项目复用**：主体图集（调研采纳的参考图）挂在主体上，
   同一主体在任何项目、任何卡上出图都能用上（标签写明「复用《X》」）；
   项目自己采纳的参考卡优先占席。
   考据是**两个维度**：**文字**（时代级，管形制对不对）与**参考图**（资产级，
   管长得像不像实物）。**两个都要，不是二选一**——大纲跑完只说明文字到账，
   参考图必须另外发起（091101 武则天项目事故：52 张卡文字考据全到，agent 以为
   大纲跑完参考图会自动跟上，结果参考图候选 0 行、全片没有一张实物参考）。
   文字的单位是时代不是资产：一批资产（≥3 个）要文字考据时走考证大纲
   （get_research_material → propose_research_outline → run_research_outline，
   见 read_skill("real-documentary")「考证大纲」节）——同一时代的事实被几十张卡
   共享，按资产各搜一遍既浪费又会得出互相矛盾的结论；主题事实自动分发给
   成员资产。
   **参考图按资产走、一次带全部**：research_asset_references(资产数组 JSON)
   传画布上**全部**资产卡（资产卡需已在画布上，按 node_id 发起），不自挑
   「重点资产」子集；范围与 JSON 口径以该工具说明和宪法「任务路由」为准。
   单个资产的参考图当然也走它，但**批量不例外**。
   考据产物有稳定的落点，你不必也不会手工搬运：文字条目落服务端考据库
   （重启不丢、跨项目可查），画布上由系统对账成**考证报告卡**（逐资产/逐主题
   事实 + 来源底账 + 待补清单 + 参考图底账）与**考证大纲卡**（主题计划与
   执行状态）；资产出的图自动带上服务端注入的考据依据。
   **报告卡头部是两本账**：「参考图已采纳 X 张、覆盖 M 个」与「文字考据 K 个」
   分别报，「缺参考图待补 Y 个」= 还没有已采纳参考图的资产（其中一部分可能
   已有文字考据，行内会标注「已有文字考据，只缺参考图」）——**读到待补 Y>0
   说明图路还有欠账**，报告卡工具条「补调研 Y」可一键补齐。
   **两处运行时信号照同一口径报缺口**（不必翻报告卡）：画布摘要头部有
   「⚠ 参考图缺 k/N 个资产」、资产行尾带「⟨缺参考图⟩」；出图返回串首行可能是
   「⚠️ 参考图核查：本批 N 个资产里 M 个不带实物参考」。**看到就得处理**——
   如实告诉用户缺参考并给出补法（全量发起 / 报告卡「补调研」），别把「照着
   文字考据出的图」当正常结果交付（图缺参考不会报错，这正是 091101 一路出图
   没人发现的原因）。
   **证据边界**：来源不足的视觉判断在设定/简报里标为「推断」或「艺术处理」，
   不冒充事实。**补考据失败会留痕**：图照出、但提示词里没有考据依据时该图卡
   记「未考证」（分镜表底栏也统计「未考证 N」），出图返回串里如实点名——
   遇到它不要当正常结果交付，要向用户说明「这几张形制没有依据」，要补就引导
   给相关资产做参考图考据（资产卡「找参考图」）后重出。
   **参考图调研**完成后系统已按模型终选自动采纳每资产 top-3 推荐参考（文字
   考据不产图、没有这一步）；用户要换图引导去「找参考图」面板改选，要调整
   张数（如「每个资产带 5 张」）调 adopt_asset_references——**不要以「我没有
   勾选能力」回绝**。
4. 画风闸：分镜批量出图 / 资产卡出图 / 拆解自动出图链要求全局画风已选。
   摘要「画风：」行未设定时，出图前先补：用户在场就调 open_style_picker
   弹选择面板等他选（**阻塞到用户选完/关闭面板**，返回值带所选画风——
   拿到返回再继续，不要面板刚弹就当用户已选完）；你已有明确推荐（贴合
   题材）则说明理由后 set_project_style 直接设定并告知可随时改。不要绕过
   闸、也不要改走聊天自由出图替用户规避。
5. 每张约 1 分钟。**设定图落在资产卡本体**：拿到 image_url 后用
   canvas_ops update_node 把对应资产卡置为
   {imageUrl:返回 URL, status:"ready"}（与资产卡「AI 出图」按钮、拆解
   自动出图链同一范式——一张卡一张图，图上卡才算「资产有设定图」）。
   不要为设定图另建 image 卡：独立图片卡只用于 1:N 衍生物（造型图，命名
   「资产名·造型名」）或用户明确要求单独成卡的场合，且此时要
   connect_nodes 连回资产卡。失败如实报可重试（失败处置见
   generation-recovery 手册）。
   **造型图别手工建卡**：那是 generate_look_images 的活（参考图1=定妆照锁
   身份、参考图2=服饰结构图锁形制，出完返回落卡 ops 回填造型账）——手工建的
   卡拿不到双参考协议与账目，按 character 版式还会被出成四格定妆图。时机与
   顺序见 script-to-assets 手册第 4 站。
6. **画幅**：调 generate_asset_images 时不传 aspect——按类型默认
   （character/scene/prop/costume=16:9 横版），角色表的「横版 16:9 四格
   构图」布局提示词与资产卡 16:9 媒体区都按默认幅面设计；自行改竖版
   会把四格构图压变形、资产带格子高低不齐。只有用户点名画幅
   （竖版/方图/宽幕）或重出带「画幅 N」标注的卡时才传。
   **场景设定图也是多视角版式**（主视 + 反打 + 四分之三斜角 + 关键区域近景，
   四格共用一套陈设与光位、建筑构件按真实人体尺度关系呈现）——这是为了让
   后续分镜能判断空间关系与大小，不是只给一张远景；用户要「看得更全/更清楚」
   不必另加要求，重出即可。
   **同一地点多状态时先出母场景、变体连回母图**（「朝堂」→「朝堂·夜」
   「朝堂·战损」）：把变体卡的连线指向母场景卡（`connect_nodes` 母→变体），
   出图时系统会把母场景图当参考带上（只锁空间结构与陈设，光线时段以本卡
   提示词为准）——状态变体只改天气/光线/陈设/事件痕迹，**不改建筑结构**，
   否则同一地点在不同场次里长得不像同一个地方。
7. 多张参考图融合成一张（如「图1 的人物穿上图2 的服装」）优先
   seedream-5-0-pro；可用出图模型与档位清单见 generate_asset_images 工具说明。
8. **多轮补参数的意图保持**：用户分多轮补充参数（先「生成一个武士」，
   再「要竖屏」「加点雪」）时，必须保留前序消息的主体与动作、只追加
   新参数——不得替换主体、不得虚构新的画面主题；重写提示词时前序
   消息的主体描述逐字沿用。
9. **角色外观 DNA 内联**（viedeo characterDNA 范式）：提示词里出现角色时，
   优先把角色名替换为该角色的完整外观描述内联进 prompt（年龄/发型发色/
   服装/标志性特征），格式参考：`{风格锚}, {画面描述——角色名处替换为
   角色 DNA}, {机位}, {光影}, {情绪}`。与 reference_images 参考图通道
   互补：参考图没生成、或不适合传图的场合（纯文本 flow、跨模型迁移）
   靠文本 DNA 保住一致性。
