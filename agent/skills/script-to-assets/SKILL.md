# 剧本 → 资产工作流

## 标准制作链

**第 1 站：剧本落 script 卡**。标题用片名（用户没提就叫「剧本」），body 放
剧本原文全文（不要截断）。
**稿子已经在画布上时别再让用户贴一遍**：用户上传的文档会自动落成一张
「[资料卡]」（摘要里标着「上传文档·正文已落卡 N 字」，正文就是文件名
对应的全文）——`read_node` 那张卡取全文即可。剧本卡是**制作载体**
（拆分镜表按钮、按集打包、分集面板都认它），资料卡是原文留档，两者可以
并存，但不要落成两张内容相同的剧本卡。

**第 2 站（分支点）：先拆分镜，还是直接拆资产？** 这是用户的决定——
**只给素材没给指令时问一句**（「先拆分镜再按分镜盘资产，还是直接拆资产？
我默认直接拆」），意图已明确（用户说了做/点名了顺序）就按用户的话走、别问。

- **分镜先**：调 generate_storyboard(剧本原文, **assets_json 留空**) →
  写回分镜表卡 → 再拆资产：调 decompose_script，入参 = **剧本原文 + 分镜表
  行文本**（read_node 分镜表卡取行）。分镜行给「本镜有哪些角色/场景/道具/
  服饰」的清单，剧本原文给「它们长什么样」的依据——**只给分镜行会编造外观
  与造型计划，那些编造会一路进到出图提示词当事实**。
  `assets_json` 留空时分镜会按剧本原名申报每镜资产，返回的
  「画布缺的资产」就是这次盘点该建哪些卡——它是这条分支最大的收益。
- **资产先（默认）**：调 decompose_script(剧本原文) → 一次 canvas_ops 批量
  建资产卡并连回剧本卡（**fromId=剧本卡id，新建卡带 id 占位符即可同批连**；
  四类资产 name 做标题、description 与 visual_notes 写进 body）→ 再
  generate_storyboard(剧本原文, assets_json=画布资产名单)。名单注入让每行
  自动引用名单内资产、名单外的幻觉名被剔除，引用绑定质量最好。

**第 3 站：资产考据（真实题材自动走）**。题材由画布 meta 决定（摘要「题材：」
行；缺省真实，用户说做动画片/架空时先 set_project_factuality("fiction")）。
**真实题材：资产卡建完就直接发起，不问**；虚构题材跳过这一站（以下两条都不用做）。

这一站是**两个维度、各走一步，不是二选一**——少走一步就少一类产物：

| 维度 | 单位 | 通道 | 产物 | 缺了会怎样 |
| --- | --- | --- | --- | --- |
| 文字考据 | 时代/主题 | 考证大纲（下面 ①②③ 三步） | 考据事实 → 注入出图提示词 | 形制靠猜（唐宋明制混搭） |
| 参考图 | 资产 | research_asset_references（**一次带全部资产**） | 已采纳参考卡 → 出图参考序列 | 图没有实物依据，只有文字约束 |

**两条都要走，先后不限**（大纲先切的唯一好处是切完你能看见主题与检索词，
心里有底；**注意检索词传不进图路**——research_asset_references 只收资产描述，
首轮搜索词由它自己的出词 flow 生成）；**大纲跑完
≠ 这一站做完**——大纲只产文字，参考图必须另外发起（091101 武则天项目事故：
52 张卡的文字考据全到、agent 按旧手册以为「大纲跑完参考图会自动跟上」，
结果参考图候选表 0 行、全片没有一张实物参考，模型照着文字硬出）。
单资产项目只走参考图那条（主题切不出来，不必强行成主题）。

- 文字考据：一批资产（≥3 个）走考证大纲——get_research_material 看现状 →
  propose_research_outline 切主题 → 用户确认 → run_research_outline。
- 参考图：research_asset_references(资产数组 JSON)，**范围默认全量**——画布上
  全部资产卡一次传入，不自挑「重点资产」子集（口径见工具说明）。完成后系统
  自动采纳每资产 top-3 推荐并物化成参考卡，收进「考据参考」折叠组连到资产卡上。

**这一站只有资产考据（文字 + 参考图）**：史实深度调研 start_deep_research
永远由用户发起，「开始制作」不含它——拿它替代这一站是 a768423e2069 事故。
年代（era）只在用户已经明说时 set_project_era——猜错会让「朝服」这类同名
资产跨项目错用（唐宋 vs 北魏），宁可留空不复用。

**第 4 站：出图（画风确认后）**，三跳且**顺序是硬依赖**：

1. **资产设定图**：generate_asset_images(资产数组 JSON，字段与拆解清单一致)。
   调研产出的考据依据与已采纳的参考卡由服务端自动带上（不必手搬——但你
   自己显式带的 reference_images 优先；**已采纳参考卡只在第 3 站的参考图
   调研跑过之后才有**，没跑过就是「只有文字约束、没有实物参考」，别默认它会在）。
   **返回直接附带「资产卡落卡 ops」**
   （把每张图挂回对应资产卡的媒体位、并带上 genPrompt/genShot 快照）——
   **先经 canvas_ops 原样应用整批 ops，再向用户汇报**：图出了 ≠ 卡上有，
   没应用就说「已落卡」是错的（091101 事故：模型口播「52 张全落卡」而画布
   一片空白）。不要自己手写 imageUrl/genShot（ops 里已带全）。
2. **造型图**：generate_look_images()（角色卡有定妆照 + 画风已选）——
   参考图1=定妆照锁身份、参考图2=绑定服饰结构图锁形制。**没有造型图，
   换装镜只能拿定妆照出、一定穿错衣服**，所以定妆照出完就接着走这步。
   返回落卡 ops，经 canvas_ops 原样应用。
3. **分镜镜头图**：generate_asset_images 时 shot 项必须带行绑定
   （"shotlist_id"=分镜表卡 id、"rid" 从 read_node 分镜行清单取）——返回附
   「分镜图落卡 ops」（每镜一张图卡摆分镜表右侧 + 资产连线 + 行挂载），
   **经 canvas_ops 原样应用整批 ops**，不要手写行 imageUrl（行图跟图卡走
   才有版本/重跑/裁剪等操作层）。
   **近景/特写要用造型图当参考而不是定妆照**：行里有造型线索（该镜穿朝服/
   囚衣/雨夜装）就带对应造型卡的图；参考图带上白底三视图会污染画面，
   reference_labels 的 type 按造型卡的父资产类型填（character），name 用
   造型卡标题。前端出图（分镜表卡工具条）近景未指定造型时会弹窗点名，
   用户可在行内 @造型名 指定——你出图时同理，别把近景镜头都按定妆照出。

**统一汇报**：文字站跑完统一汇报（资产清单 + 分镜镜数 + 调研范围——**文字考据
几个主题、参考图覆盖几个资产都要报数**，只报一个会让用户以为调研做全了），出图
待画风确认继续。用户要增删资产/改分镜时直接用 canvas_ops 改画布，不要重新
拆解；回看剧本原文用 read_node(剧本卡id)。

**拆解契约**（第 2 站建卡时用）：description=本体外观事实（剧本没写的按类型/
年龄感补全具体外观，禁止剧情转述、禁止描述里出现其他角色）；visual_notes=
本体色彩/材质/体态，不写光线氛围镜头调度。拆解 flow 已按此产出，转述清单
给用户时照抄别改写成剧情描述。
**服饰卡的取舍判据**（命中任一即建）：①近景及以上能看清服装主体；②承载
时代/身份/职业信息（官服、囚衣、制服、礼服、铠甲）——**不以「复用次数少」
为不建的理由**：只在一场戏里出现但被近景拍到的服装（囚衣、礼服）同样必须
建，否则该镜只能拿基础角色图加文字硬生。
**返回里带「画布缺的资产」时必须处理**：那是分镜申报了、画布上没有对应卡的
名字（换装服饰/关键道具漏拆的发现回路）——逐名核对是否真在素材里：在的按
类型补建资产卡（character/scene/prop/costume）并在回复里点名补了哪几个，
纯属编造的丢弃并说明；补完再出图。

## 多集项目（一张剧本卡 = 一集）

纪录片/系列一部多集时：

- **每集一张剧本卡**（标题写集名）；该集产出（分镜表/镜头图/视频/成片）用
  `episodeId`=该剧本卡 id 归属——前端「拆分镜表」与出图/出视频落卡会自动
  继承，聊天侧建卡时在 ops 里带上 `episodeId`。
- **资产只拆一次、跨集共享**：角色/场景/道具/服饰卡**不带** episodeId，
  后续每集复用同一批资产卡（引用绑定与参考图一致性的前提）。
- **按集循环**：第 N 集 = 剧本落卡（带集）→ 分镜表（带集）→ 出图/出视频 →
  成片；资产拆解只在第一集做一次，其余集直接用资产名单。
- 画布摘要里剧本卡行显示「第 N 集 · 本集：分镜表 1 · 镜头图 12…」，产物卡行尾带
  `⟨集名⟩`；`canvas_query(episodeId=剧本卡id)` 一次取全本集的卡。
- **集号 `episodeNo`**（1 起）建 script 卡时自动排到末尾，通常不用管；用户要
  调集序时 `update_node` 给目标集号即可（前端分集面板点一次 ↑↓ 会整体归一）。
- 交付：剧本卡工具条「下载本集」按集打包媒体（≥2 张剧本卡时才出现）；
  底坞「分集」面板列全片集目录（点集聚焦、↑↓ 重排）。
- 选题池认领系列选题时可「按分集落卡」：总纲 note + 每集一张剧本卡一次落好、
  集号已排好——接着从第一集走标准链即可。

## 长镜头 / 多段动作计划

用户要求"长镜头计划"或描述一段含多个动作节拍的连续戏时：按动作节拍拆成
多张 storyboard 卡——镜号用同一镜号加段号（如 03a/03b/03c），每段
duration 2-5 秒，body 写该段的画面描述与节拍动作，整镜的 cameraMove 保持
一致（保证镜头连续性），按时间顺序 connect_nodes 相邻连线。
用户在分镜卡上会用「导演台」补摄影语言（body 的【摄影】段），尊重它，
不要改写。

## 分镜（storyboard）卡字段规范

title=镜头名，body=画面描述（谁、在哪、做什么）；add_node / update_node
可带 shotNumber（镜号，如 01）、shotSize（远景/全景/中景/近景/特写）、
cameraMove（运镜，如 推、拉、摇、跟、固定）、duration（如 3s）、
dialogue（台词/旁白）。单镜头画面卡按顺序连线，镜号从 01 递增。

## audio / compose 卡

audio（音频）卡：配音 / 音效 / BGM，音频源由用户在卡片上上传（audioUrl），
你只负责建卡与连线。
compose（合成）卡：把多张视频卡按顺序连线到它，用户点卡片上的「合成成片」
按钮由服务端 ffmpeg 拼接——你只负责建 compose 卡并 connect_nodes 把视频按
镜号顺序连上，不要自己生成合成结果。
